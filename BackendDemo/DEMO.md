# Talk&Talk 内容安全审核 — 老板演示脚本

> 预计时长：**5–7 分钟**  
> 演示方式：浏览器打开 Web 审核后台（规则 + DeepSeek 双层审查，需联网）

## 一句话定调

「用户发消息后，系统先自动审查；高风险直接拦截并生成工单，管理员在这套后台看证据、做处置，边界样本还能沉淀成训练数据。」

---

## 会前检查清单（演示前 5 分钟）

- [ ] Node.js 版本 ≥ 22（`node -v`）
- [ ] 已配置 DeepSeek API Key（`BackendDemo/.env` 中有 `DEEPSEEK_API_KEY`）
- [ ] 启动服务：

```bash
cd BackendDemo
npm start
```

- [ ] 浏览器打开并全屏：`http://localhost:8787`
- [ ] 点击右上角 **「重置演示数据」**，恢复干净初始状态
- [ ] 左下角徽章显示 **「AI 模式开启」**，model 显示 `deepseek-chat`
- [ ] （可选）运行自检脚本：`./scripts/prep-demo.sh`

### 健康检查（附录）

```bash
curl -s http://localhost:8787/api/health | jq '.data'
# 期望: status="ok", moderation.connected=true, moderation.provider="deepseek"
```

### 离线兜底（无网络时）

```bash
DISABLE_DEEPSEEK=1 npm start
```

此时仅规则引擎，左下角显示「规则引擎兜底」。

## 演示主线（照着点、照着讲）

### 第 1 步：开场（30 秒）

**操作：** 页面加载完成后，先指一下顶部统计区和左侧「审核队列」，以及左下角 **AI 模式开启** 徽章。

**讲解：**

> 这是 Talk&Talk 的内容安全审核后台。用户聊天、社区发帖都会经过「规则引擎 + DeepSeek」双层审查；高风险内容会被拦截并进入人工复核队列。

**预期画面：**

- 待处理工单 ≥ 1
- block 违规 ≥ 1
- 审核队列里已有 4 条预置工单

---

### 第 2 步：展示已有高风险工单（1 分钟）

**操作：**

1. 在左侧 **审核队列** 中点击第一条：`聊天拦截：线下见面 + 酒店暗示`（mc1）
2. 右侧 **工单详情** 展开，指出：
   - 决策：`block`
   - 风险：`high`
   - 命中规则：`contact.offline`、`sexual.explicit`
   - 状态：`humanReview`（待人工复核）

**讲解：**

> 这条是系统已经拦截的高风险内容——线下邀约加酒店暗示。规则引擎直接 block，并生成工单交给管理员复核，不会当作正常聊天放行。

---

### 第 3 步：查看会话证据（1 分钟）

**操作：**

1. 滚动到下方 **会话证据** 区域
2. 在会话下拉框选择 **周映 · 王五**（c3）
3. 指出聊天记录里的 **系统安全提醒**，以及违规消息旁的风险标签

**讲解：**

> 每条工单都能关联到具体会话上下文。违规内容被拦截后，用户看到的是平台安全提醒，而不是让违规消息留在正常聊天流里。

---

### 第 4 步：现场拦截新违规（2 分钟）

**操作：**

1. 滚动到 **违规示例库**
2. 点击 **「引导私下联系」** 卡片（文案：`我们加微信聊吧，平台里说话太麻烦了。`）
3. 下方 **复核与标注** 区会自动填入文本
4. 点击 **「发到会话生成工单」**（橙色按钮）
5. 等待 toast 提示「已拦截并生成工单」
6. 回到 **审核队列**，确认顶部出现新工单
7. 顶部 **block 违规** 计数 +1

**讲解：**

> 我现在模拟用户发了一条「加微信」的消息。规则引擎实时判定为 block，消息不会写入聊天记录，同时自动生成工单进入队列。私联、线下、转账这类高风险内容都会在发送环节被拦住，不需要等 AI。

**预期结果：**

| 字段 | 期望值 |
|------|--------|
| 决策 | `block` |
| 风险 | `high` |
| 命中规则 | `contact.wechat` |
| 模式 | `rules` / `skipped_rule_block` |
| 新工单状态 | `humanReview` |

---

### 第 5 步：人工处置工单（1 分钟）

**操作：**

1. 在审核队列中选中刚才生成的新工单（或任意 `humanReview` 工单）
2. 在工单详情底部填写备注，例如：`确认引导私联，维持拦截`
3. 点击 **「确认违规」**
4. 观察工单状态变为 `resolved`，顶部 **已处理** 计数增加

**讲解：**

> 自动拦截之后，管理员可以在这里做最终处置——确认违规、驳回误报或升级处理。每次操作都会留下日志，方便追溯。

**可选补充：** 再选一条 `pending` 工单，点 **「驳回」** 演示误报处理流程。

---

### 第 6 步：边界对比 — AI 与正常放行（1 分钟）

**操作：**

1. 在 **违规示例库** 点击 **「广告引流」**（`兼职赚钱，代理推广，加我了解详情。`）
2. 点击 **「立即审查」**
3. 查看审查结果区，指出 `AI deepseek-chat` 与规则合并结果

**讲解：**

> 边界内容先过规则引擎，再由 DeepSeek 补充判断。广告引流这类灰色地带，两层一起给出更稳的决策。

**再演示正常放行：**

1. 点击 **「正常倾诉」** → **「立即审查」**
2. 决策为 `allow`，不会生成拦截工单

**预期结果（正常倾诉）：**

| 字段 | 期望值 |
|------|--------|
| 决策 | `allow` |
| 风险 | `low` |

**可选补充（warn 边界）：** 点击「索要隐私」→ 立即审查，决策为 `warn`。

---

### 第 7 步：收尾（30 秒）

**操作：**

1. （可选）在标注区保存一条样本，点 **「导出样本」** 展示 JSON
2. 点击右上角 **「重置演示数据」**

**讲解：**

> 边界案例可以标注沉淀成训练样本。这套后台从自动拦截到人工处置是完整闭环，演示数据一键重置，可以反复演示。

---

### 第 8 步（可选加分）：iOS App 发消息 → Web 后台同步（1 分钟）

**操作：**

1. 确认 BackendDemo 已启动
2. Xcode 运行 iOS App（模拟器），进入与 **林屿** 的聊天
3. 确认聊天页显示 **「后端已连接 · deepseek-chat」**
4. 在 App 里发送：`我们加微信聊吧`
5. 回到 Web 审核后台，点 **「刷新」**，查看新工单和会话证据

**讲解：**

> 手机端和审核后台已经打通——用户在 App 里发的消息走后端审查，管理员在同一套后台看到拦截结果和证据链。

## 翻车预案

| 情况 | 处理 |
|------|------|
| 页面数据乱了、工单太多 | 点 **「重置演示数据」** |
| 服务无响应 | 终端 `Ctrl+C` 后重新 `npm start` |
| 端口被占用 | `PORT=8788 npm start`，浏览器改访问 `http://localhost:8788` |
| DeepSeek 连不上 / 现场无网 | `DISABLE_DEEPSEEK=1 npm start`，改演示规则引擎兜底 |
| 左下角显示「规则引擎兜底」 | 检查 `.env` 中 `DEEPSEEK_API_KEY` 是否配置 |
| iOS 显示「仅本地模式」 | 确认 BackendDemo 已启动；模拟器默认 `http://127.0.0.1:8787` |

## 审查架构说明

当前 `src/server.js` 的 `moderateText()` 流程：

1. **规则引擎**（`ruleBasedModeration`）— 高风险直接 block，不调 API
2. **DeepSeek**（`deepseekModeration`）— 边界内容补充判断，与规则分数取 max

Web 审核后台无需因换 API 提供商而改动 UI。
