# Talk&Talk v0.1 · 浅彩卡牌剧场

日期：2026-09-01
状态：**本地实现与验证完成；尚未发布**
首发表面：微信小程序 + `/api/v1`

## 摘要

v0.1 将 Talk&Talk 重构为一套浅色、低饱和、多元卡牌的陪伴体验。卡牌通过正向叠层形成空间感，安静小物提供品牌记忆，有限动效负责反馈而不持续抢占注意力；支付、退款、身份、危机、证据和审核继续使用稳定、严肃的状态表达。

## 主要变更

### 微信小程序

- 31 个页面、18 个共享组件迁移至 UI4。
- 首页 Listening Lounge、发现 Garden、消息 Post Office 等场景加入叠卡与克制卡通元素。
- 后层卡保持真实命中；首页与发现动效有限并可终止。
- 支持 light/dark、320/390/430，以及 `motionOff` 静态终态。
- 主界面文案减少 48.7%，完整交易、隐私与平台规则由现有法律页承接。

### 公开 Web

- 五个可索引路由采用同一浅彩卡牌剧场语言。
- 首页 M4，服务流程/关于 M3，合作 M2–M3，安全页保持 M0–M1。
- 移除重复 FAQ、品牌解释和收尾 CTA；五路由文案减少 64.1%。
- 生产锁继续拒绝私有 Web App、BFF、登录、订单、消息与工作台表面。

### Admin / Independent Review

- 登录故事区使用不同身份色与克制纸片剧场。
- 登录后的案件、证据、支付、身份、安全、审计和受控操作保持平面 M0/M1。
- Admin 与 Review 的账号、会话、TOTP、权限和审计域继续分离。

### 可信边界

- 当前只保留文字首发；语音/媒体能力不会因 UI 出现而被宣称开放。
- 支付成功以服务端微信结果为准；退款窗口和规则版本固定在订单上。
- 危机页面保留 110/120、网络失败和现实支持路径，不使用庆祝或卡通动效。
- 未读取到真实资料、身份、权限或渠道结果时保持错误/未知，不生成看似合理的数据。

本说明不是发布收据。v0.1 提交集已在独立 clean worktree 复验并合并 `main`；原开发工作区仍保留未纳入 `main` 的历史与中间文件。当前没有创建标签或 GitHub Release。

- 真实消费者、陪伴者、Admin、Review 的授权端到端流程；
- 真实微信登录、身份授权、小额支付、回调、退款与结果同步；
- 微信真机帧率、长列表、系统字体、原生控件与触控；
- staging / 体验版 / 生产域名、CDN、监控与回滚演练；
- AppID、支付商户、模板消息、TRTC 与外部合规审批；
- 独立发布复核、提交、推送、Upload、审核与部署授权。

准确表述：**Talk&Talk v0.1 UI4 已在本地实现并通过约定的代码、开发者工具和静态视觉门禁；尚未对外发布。**
