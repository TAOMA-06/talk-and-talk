## 复审中实际发现并修复的问题

1. 支付恢复迁移重复创建旧索引，空库部署会在第 32 条迁移失败；已改为兼容既有索引的迁移并从新空库重验 34/34。
2. PostgreSQL advisory lock 返回 `void`，Prisma 7 pg 适配器无法反序列化，真实订单创建会 500；已转换为受支持的标量返回，并覆盖订单与客服两处锁。
3. 旧 E2E 通过直接改数据库绕过陪伴者确认、支付保留和商业档案双审；夹具已改为走正式 API，并验证两个重叠预约只能有一个确认成功。
4. 预下单和退款在调用微信前缺少完整持久恢复窗口；现已先落唯一引用，再调用外部接口，并由数据库 worker 查询恢复。
5. 固定频率退款查询可能消耗微信配额且多副本重复执行；现改为数据库查询计划、递增退避和抢占租约。

非阻塞观察：`@prisma/adapter-pg 7.8.0` 在部分并发 E2E 中会由其内部查询解释器触发 pg 8 的弃用警告。当前依赖限制为 pg 8 主版本，73 项 E2E 均通过；升级 pg 9 前必须先升级/验证 Prisma 适配器，不能直接放宽主版本。
