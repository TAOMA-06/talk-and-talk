# 聊天审核 v2 运行说明

## 范围与原则

本版本只覆盖微信小程序与 NestJS API；历史 iOS 工程不在交付范围。文本、图片和不超过 60 秒的语音都进入同一投递生命周期：

```text
提交 → 自动审核 → published / pendingReview / blocked → 人工复核 → 处置或申诉
```

`queued` 用于尚在媒体审核中的消息。仅 `published + participants` 可被对方读取；待审、拦截和已移除内容不会泄露给接收方。

## 决策与安全处置

- 规则层先于模型执行，覆盖 Unicode、空格/标点、常见谐音与拆字混淆；模型只能提高风险，不能降低硬规则结果。
- 审核同时使用最近 10 条已发布会话、24 小时高风险信号、图片 OCR / 图像结果和语音转写。
- 自伤或暴力风险会显示安全求助提示、设为 `critical`，SLA 为 30 分钟并直接进入 `humanReview`；系统不自动联系外部机构。
- `warn` / `review` 暂缓发送；`block` 永不向对方展示。

## 限言、申诉与审核员权限

- 24 小时内两次高风险拦截：自动创建 24 小时、仅发送聊天限言。
- 30 天内三次人工确认违规：最新案件升级为 `critical/humanReview`，由审核员决定是否采用既有全局账号限制。
- 只有审核员可以延长或解除聊天限言；系统不会自动全局封禁。
- 严重拦截、聊天限言、人工确认违规各允许一次申诉。申诉成立会放行关联消息并撤销关联限言。

## 媒体与留存

客户端先申请短时、受限上传指令，再将完成的资产附加到消息。服务端验证上传归属和完整性；客户端不会获得长期存储地址。

- 正常媒体：30 天后删除并在客户端显示过期占位。
- 案件关联媒体：自动提升至 180 天证据留存。真实存储适配器必须使用加密存储与受权签名读取 URL。
- 媒体审核不可用：30 秒、2 分钟、10 分钟指数退避三次；仍失败则进入人工队列，绝不自动放行。

## 发布开关

默认 `MEDIA_FEATURE_ENABLED=false` / `MEDIA_PROVIDER=disabled`。内置 `mock` 只用于开发和测试。启用真实媒体前必须完成：

1. 注册并审查真实 `MediaStorageProvider` 与 `MediaAnalysisProvider`；上传验证必须校验对象大小、MIME、摘要，证据必须加密。
2. 在 staging 执行迁移、图像 OCR / 语音转写、失败重试、签名预览和 180 天留存验收。
3. 先启用影子记录，再启用文本状态，最后仅在适配器齐备的环境打开图文语音入口。

详细端点和审核员动作见 [admin-moderation-api.md](./admin-moderation-api.md)。
