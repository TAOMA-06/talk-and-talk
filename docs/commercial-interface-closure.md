# Talk&Talk 商用界面闭环与验收台账

更新时间：2026-08-01

## 目标与口径

本台账覆盖当前正式发行范围中的微信小程序、NestJS API、独立审核工作台和商业运营后台。完成的定义不是“页面存在”或“接口存在”，而是：

1. 用户、陪伴者或工作人员能通过受保护的正式入口完成任务。
2. 状态来自真实 API；生产缺少外部提供方时失败关闭，不展示伪造成功。
3. 金融、身份、审核、客服和账号治理动作有权限、二次确认、理由、审计和可恢复状态。
4. 新旧订单、支付、退款、排班和通知语义保持兼容，并通过相关构建、单测、E2E 与客户端 smoke。
5. 外部资质、真实 KYC、微信商户、TRTC、媒体审核、法务和运营值班只在取得可核验证据后标记通过。

正式发行面固定为：普通用户和陪伴者共用微信小程序；商业员工使用 `/admin/`；独立审核员使用 `/review/`；三者以 NestJS `/api/v1` 为权威状态源。`frontend/ios`、消费者 Web 和本地演示均不参与本轮放行。

第二轮市场对标、逐能力结论、刻意不复制项和外部 P0 见 [商用界面市场交叉审查（2026-08-01）](./commercial-market-cross-audit-2026-08-01.md)。报告曾发现的仓库 P0/P1 已逐项实现并进入自动回归；这只代表仓库闭环，外部 P0 证据未齐前生产仍为 No-Go。

## 不可触碰边界

- 产品仍是线上陪伴，不使用心理治疗、诊断或疗效承诺。
- 身份证、银行卡和税务原文不进入普通业务数据库、日志或前端；只保存受控外部引用和掩码。
- 审核部门与普通用户、商业运营人员保持独立身份、权限和审计。
- 支付和退款以微信权威查询/通知为准；受理、处理中和成功不能混为同一状态。
- 不以虚拟币、礼物、财富榜、付费排名或付费认证作为本轮商用闭环。
- 不把本地 Mock、测试构建或静态页面部署当作真实生产链路证据。

## 内部岗位与最小权限

独立审核员继续使用 `ReviewStaff`。普通商业员工不得用审核令牌访问商业后台，审核员也不得用审核令牌访问订单、财务或用户运营数据。

| 岗位 | 可读 | 可写 | 明确禁止 |
|---|---|---|---|
| `support` | 本人队列中的工单、关联订单必要事实 | 认领、补充处理记录、非资金结论、发起退款建议 | 批准退款、结算、KYC 核验、账号封禁 |
| `finance` | 支付、退款、收益、结算、追偿及必要掩码 | 退款复核、结算证据、追偿复核 | 读取聊天正文、内容审核、修改陪伴者公开资料 |
| `supply` | 陪伴者申请、KYC 外部引用、协议、培训和质量 | 核验/驳回、发布/暂停、培训与质量处置 | 支付退款、客服私密陈述、内容审核 |
| `operations` | 聚合经营指标、订单状态、供给和 SLA | 运营策略及非资金配置 | 读取原始身份/收款信息、批准退款、内容审核 |
| `admin` | 必要的全局应急视图 | 受审计的超级管理员动作 | 绕过双人复核、复用审核部门身份或删除审计 |
| `reviewer` / `lead` | 独立审核案件和受控证据 | 审核处置；高风险动作仅 `lead` | 商业运营、客服、资金、KYC 和普通用户登录 |

前端隐藏按钮只能改善可用性，不能代替服务端角色校验。资金、KYC、账号和高风险审核动作还必须满足双人或负责人约束。

## 验收矩阵

| 工作流 | 必须交付的界面与能力 | 完成条件 | 状态 |
|---|---|---|---|
| 用户首次进入 | 需求快速入口、常见场景、边界与风险分流 | 能从需求进入可解释推荐或安全资源，不采集不必要敏感信息 | 仓库闭环 |
| 发现与详情 | 即时/预约区分、信任维度、服务范围、规则和试听元数据 | 公开信息来自审核后的服务端数据，缺失项不伪造 | 仓库闭环 |
| 下单与支付 | 下单前确认、订单详情、支付结果和权威同步状态 | 创建订单前二次确认；模糊支付结果可查询、不可重复支付 | 仓库闭环 |
| 履约 | 通话前检查、时间/网络状态、安全退出、异常与举证 | 真实授权；断线、弱网、迟到、缺席和紧急退出有明确后续 | 仓库闭环；真机门禁 |
| 服务后 | 评价、退款/投诉、固定陪伴者、复购和资源 | 结果归属原订单，公开评价和私密反馈边界不变 | 仓库闭环 |
| 消息与通知 | 会话、订单上下文、事务通知、偏好和失败状态 | 站内事实可兜底；外部通知失败不丢失原始状态 | 仓库闭环；模板审批门禁 |
| 安全与客服 | 案件列表、详情、证据、SLA、结果、申诉与危机分流 | 举报不是只有回执；普通客服与紧急安全通道分开 | 仓库闭环；人员/SOP 门禁 |
| 账号与隐私 | 登录设备、黑名单、数据权利、注销进度、账单/发票入口 | 法定自助入口在限制状态下仍可访问；交易记录不被误删 | 仓库闭环；法律批准门禁 |
| 陪伴者入驻 | 申请、KYC 引用、协议、审核、公开资料和状态 | 双人复核边界保留；未核验不能发布或接单 | 仓库闭环；真实 KYC 门禁 |
| 培训与质量 | 课程、考试、复审、指标、警告、处罚和申诉 | 关键边界和风险能力可验证；质量指标来自真实订单/案件 | 仓库闭环；人工考核门禁 |
| 排班与订单 | 周期规则、例外/休假、一次性窗口、异常与举证 | 仅 owner 可操作；生成草稿需独立激活并重新校验 | 仓库闭环 |
| 收益与结算 | 明细、平台费、冻结、结算、提现、追偿和税务掩码 | 资金动作双人复核、幂等、可审计；外部转账不伪造 | 仓库闭环；财税/真实付款门禁 |
| 商业运营后台 | 经营、供给、订单、客服、退款、日账单对账、财务、账号与审计 | `/admin/` 不再只是审核跳转；危险动作默认只读并二次确认 | 仓库闭环 |
| 独立审核后台 | 认领/交接、SLA、附件、处置、导出权限和审计 | ReviewStaff 身份不与 admin/user 混用，停用后不能获得新案件 | 仓库闭环 |
| 发布验证 | 单测、构建、迁移、E2E、客户端 smoke、安全与产物检查 | 变更引入的失败清零；外部未验证项明确保持 No-Go | 自动验证通过；隔离 E2E 依赖待授权复跑 |
| 竞品交叉审查 | 国内外同类产品逐页复核、遗漏修补 | 基于当期官方资料；事实、判断和未知分开记录 | 第二轮已审查；仓库 P0/P1 已清零 |

## 冻结基线与本轮验证

开始改造前已记录以下本地证据，后续必须至少保持同等结果：

- `backend/api`: `npm test` 通过，79 个测试套件、587 项测试。
- `frontend/miniprogram`: `node scripts/validate.mjs` 通过 development structure gate，14 个页面、5 个 Tab；正式 AppID 尚未提供。
- `frontend/miniprogram`: `node scripts/smoke.mjs` 通过，覆盖 consent/legal、373 次 API 调用、Mock/真实支付分支与 HTTPS/Cloud Run transport。
- 工作区开始时已有用户修改：`backend/api/scripts/acceptance-smoke.sh`、`backend/api/src/auth/guards/jwt-auth.guard.ts`、新增的 guard spec，以及未跟踪的 `frontend/web/`；本轮不得覆盖或据为己有。

本轮最终自动证据：

- `backend/api`: 121 个单元测试套件、1022 项测试通过；TypeScript 构建通过；39 项部署预检、静态后台和 OpenAPI 契约检查通过。
- 微信日账单专项：provider、parser、service、worker、DTO、controller、商用 readiness 与后台契约均通过；无账单可人工重拉，后续取得真实账单会关闭旧缺账异常，但新差异仍保持开放。
- `frontend/miniprogram`: TypeScript 通过，30 页面、5 Tab 结构校验通过；runtime smoke 覆盖 691 次 API 调用及法律/支付分支。
- 隔离 PostgreSQL fresh DB：87 个迁移顺序全部成功；ReviewStaff 停用分配触发器和历史注销 retention ledger 回填在真实数据库中通过。
- 完整 E2E 首跑只命中旧本地数据库未迁移及 Redis 非专用库保护；创建隔离 PostgreSQL 的沙箱授权审核本身失败，因此没有把 E2E 误报为通过。该复跑属于当前环境验证门禁，不改变已通过的单元、迁移和 smoke 证据。

## 外部门禁

下列项目需要真实企业账户、设备、供应商、人员或签字，代码完成后仍不能自动判定通过：

- 微信小程序主体、类目、隐私接口、域名、商户、支付/退款、订阅消息审批。
- 真实 KYC、电子签约、税务/收款对象和受控证据库。
- TRTC 双真实设备、权限、弱网、重连、紧急关闭和服务时间验收。
- 生产媒体存储与审核提供方、夜间人工复核和危机升级演练。
- 法务确认产品边界、协议、隐私、退款、未成年人、发票与税务。
- 独立生产数据库/Redis/TLS、备份恢复、监控告警、容量和值班。
- 受控真钱支付、退款、结算、追偿和账号注销全链路证据。

这些项目在取得证据前统一标记为“上线门禁”，不能用环境变量、演示数据或人工口头确认替代。
